iosESP

The one-board ESP32 Wi-Fi bridge for WarBLE Go. iPhones can't scan Wi-Fi — this board does it for you and streams every network it hears to the app over Bluetooth. No pairing, no setup, no terminal.

Download iosESP firmware (.zip) #wardriving on Discord

Prebuilt for ESP32-C3 · C5 · C6 · S3 (and the source for any other BLE-capable ESP32). ESP32-S2 has no Bluetooth and won't work.

Flash it

  1. Unzip. Pick your chip's folder under firmware-bins/.
  2. Plug the board in over USB and run (replace <chip> and <PORT>):
esptool --chip <chip> -p <PORT> erase_flash
esptool --chip <chip> -p <PORT> -b 460800 write_flash 0x0 wardrive-bridge-merged.bin

One merged file at 0x0 — the offsets are baked in (the C5's bootloader lives at 0x2000; the merged image already handles that, so don't hand-flash a C5 bootloader to 0x0). No esptool? ESP Web Flasher in Chrome works too: connect, pick the merged .bin, flash at 0x0.

  1. Power the board. In WarBLE Go turn the Wi-Fi bridge on once — it links by itself from then on.

Default LED is the onboard WS2812 on GPIO 8 (most C3/C6 devkits). A different pin or a plain LED: change it in idf.py menuconfig → WarBLE Wardrive Bridge and rebuild from source/. The bridge works either way.

Running stock GhostESP? It links but won't scan

Stock GhostESP's bridge is a two-board design: a Bluetooth "core" wired to a second "peer" radio that does the scanning. A single stock board connects to WarBLE Go fine, then answers every command with comm link down — linked, 0 networks. WarBLE Go tells you when it sees that.

Two ways out:

  • Flash iosESP (the zip above) — purpose-built, one board, nothing to configure. Recommended.
  • Keep full GhostESP and apply the ghostlink-solo/ patch included in the zip: it lets an unpaired board scan on its own chip. Instructions in that folder's README.
